在 CC Switch 里用 Token Station 配置 Claude Desktop

CC Switch 是一个桌面工具，用来集中管理 Claude Code、Claude Desktop、Codex、Gemini CLI、OpenCode、OpenClaw 和 Hermes 的 Provider、MCP、Prompts 与 Skills。它的价值在于：你不需要手工改一堆 JSON、TOML 或 env 文件，而是在同一个界面里添加 Provider、切换 Provider，并让 CC Switch 写入各个工具自己的配置。

这篇只讲一个场景：把 Token Station 加进 CC Switch，然后以 Claude Desktop 为例使用它。重点不是 Claude Code。CC Switch 官方文档说得很清楚：Claude Code 和 Claude Desktop 是两个独立入口。Claude Code 用 ~/.claude/settings.json；Claude Desktop 用自己的 3P profile 配置，在 CC Switch 里也显示为单独的 “Claude Desktop” 面板。

先安装 CC Switch

macOS 用户最简单的安装方式是 Homebrew：

brew install --cask cc-switch

Windows、Linux 或手动安装，可以去 CC Switch Releases 下载对应安装包。首次打开时，如果它提示导入已有工具配置，可以先跳过；我们下面会单独为 Claude Desktop 添加一个 Token Station Provider。

添加 Token Station Provider

在 CC Switch 左侧选择 Claude Desktop。如果看不到这个入口，去 Settings → General → Homepage Display，确认 Claude Desktop 没有被隐藏。

进入 Claude Desktop 面板后，点右上角的 + 添加 Provider。Token Station 不是 Claude Desktop 的官方登录模式，也不应该当作 Claude Desktop 官方账号处理；这里选择自定义 Provider。

字段建议填写
名称Token Station
API Key你的 Token Station key
Endpoint / Base URLhttps://models.bytefuture.ai/v1
API FormatOpenAI Responses API
Needs model mapping开启

为什么要选 OpenAI Responses API？因为 Token Station 的 OpenAI 兼容入口在 /v1/responses，而 Claude Desktop 原生只认识自己的 Claude role 模型。CC Switch 的本地路由会负责把 Claude Desktop 发出的请求转换成上游 Provider 能理解的格式。

配置 Claude Desktop 的 model mapping

Claude Desktop 现在会拒绝不属于 claude-sonnet-*、claude-opus-*、claude-haiku-* 这三类 role family 的模型名。也就是说，你不能直接把 openai/gpt-5.5 写进 Claude Desktop 的模型菜单里。官方文档建议：非 Claude 模型、旧版 Claude ID、Kimi、DeepSeek、GLM、DouBao、OpenAI、Gemini 这类模型，都应该走 Model Mapping Mode。

在 Token Station Provider 里打开 Needs model mapping，然后按角色填入真实上游模型：

Claude Desktop role菜单显示名Requested model说明
SonnetGPT-5.4 Miniopenai/gpt-5.4-mini日常对话、写代码、读文档的默认档。
OpusGPT-5.5openai/gpt-5.5复杂推理、长上下文、架构设计。
HaikuGPT-5.4 Nanoopenai/gpt-5.4-nano短任务、低延迟、低成本。

如果你只想先跑通，也可以只填 Sonnet。CC Switch 文档里说，空白 role 会继承第一个已填写的模型（优先 Sonnet），所以 Haiku 这类调用不会因为没填而完全不可用。等确认能用后，再分别补 Opus 和 Haiku。

打开本地路由

Model Mapping Mode 不是直接让 Claude Desktop 访问 Token Station。它会让 Claude Desktop 连接到 CC Switch 的本地网关：

http://127.0.0.1:15721/claude-desktop

CC Switch 在本机做四件事：给 Claude Desktop 暴露安全的 Sonnet / Opus / Haiku 路由；把 Claude Desktop 选择的 role 映射到真实的 Token Station 模型；按需要转换 Anthropic / OpenAI / Gemini API 格式；再用你保存在 CC Switch 里的 Token Station key 去请求上游。

本地路由开关默认可能隐藏。按官方文档路径打开：

Settings → Routing → Local Routing
打开 Show Routing Toggle on Main Page

回到 Claude Desktop 面板，打开右上角的 Claude Desktop local routing toggle。状态为 On 时，本地网关通常运行在 127.0.0.1:15721。Direct mode 不需要这个开关，但 Token Station 这种 OpenAI Responses + model mapping 的配置需要保持 CC Switch 运行，并保持本地路由开启。

启用并重启 Claude Desktop

Provider 配好以后，在 Token Station 卡片上点 Enable。然后完全退出 Claude Desktop，再重新打开。这里不要套用 Claude Code 的经验：Claude Code 可以热切换 Provider 数据，但 Claude Desktop 不会热加载 3P profile。每次切换 Provider 后，都要完整重启 Claude Desktop。

重启后，在 Claude Desktop 的模型菜单里，你应该看到 model mapping 里填写的显示名，比如 GPT-5.4 Mini、GPT-5.5、GPT-5.4 Nano。选一个模型，发一条简单消息，例如：

请只回复：pong

如果它返回 pong，说明 Claude Desktop → CC Switch 本地路由 → Token Station → 上游模型 这条链路已经通了。

常见问题

  • Claude Desktop 还是没变化。完全退出并重新打开 Claude Desktop。它通常只在启动时读取 3P profile。
  • 非 Claude 模型不出现在菜单里。不要把真实模型名直接写进 Claude Desktop profile。开启 Needs model mapping，通过 Sonnet / Opus / Haiku role 映射真实模型。
  • 请求失败。确认 CC Switch 还在运行，本地路由是 On，Token Station API key 和 endpoint 正确，model mapping 至少有一个 Requested model。
  • Direct mode 失败。Direct mode 只适合原生 Anthropic Messages API 且模型名能被 Claude Desktop 识别的 Provider。Token Station 这里建议使用 OpenAI Responses API + Model Mapping Mode。
  • 想回到 Claude Desktop 官方登录。在 CC Switch 里选择 Claude Desktop Official，点 Enable，然后重启 Claude Desktop。

总结

用 CC Switch 接入 Token Station 的关键不是“把一个 base URL 填进 Claude Desktop”，而是走 Claude Desktop 面板里的 Provider + Model Mapping。Token Station 负责统一模型入口；CC Switch 负责把 Claude Desktop 认可的 Sonnet / Opus / Haiku role 映射到真实模型，并在本地完成格式转换。

配置完成后，Claude Desktop 可以继续保持原来的使用方式，但背后的模型已经可以换成 Token Station 上的 openai/gpt-5.5、openai/gpt-5.4-mini、openai/gpt-5.4-nano，或者你在 Token Station 里可用的其他模型。
