A router trained on your traffic, then on its own results.

Static routing rules go stale as your workload shifts. Token Station's router starts with fast heuristics, then trains a model on what your company actually sends and keeps retraining it.

Routing by confidence, not by rule.

Every request gets a confidence score. Above your threshold it stays on your own servers; below it, it goes to a cloud model. You set the threshold, and you can move it without redeploying.

Each decision is logged with how it turned out. The next retrain learns from those outcomes, so every router version starts where the last one stopped.

The router supports several routing methods, from deterministic heuristics to a trained model. The trained router is built on Jev, a discriminative model that returns a decision and a calibrated confidence score instead of generated text.

Technical questions, answered.

Does routing add latency to every request?

The routing decision is a classification, not text generation, so it adds milliseconds rather than seconds, well below the time of any LLM call. Locally routed requests skip the round trip to a cloud provider, which often makes them faster than cloud calls. Pilot dashboards show the measured overhead.

Will routing to smaller models hurt quality?

The router sends a request to a local model only when its confidence is above a threshold you set (default 0.85). Below that, it falls back to the cloud. RouteLLM (ICLR 2025) showed 2× cost savings with no measurable quality regression on real-world benchmarks, and Token Station's router improves on that baseline by training on your own data.

Which local models are supported?

Llama 3 (8B, 70B), Mistral 7B, Phi-3 (mini, small, medium) and Qwen 2.5, with new models added quarterly. All run through the Olares runtime with no manual CUDA setup. You can also plug in any model that exposes an OpenAI-compatible endpoint.

What data do the router and the PII model train on?

You choose. By default they train only on metadata about your requests: token counts, task categories, confidence scores and the quality signals you opt into. You can also allow training on request content, which lets the router and the PII masking model learn your own formats and identifiers more precisely. Either way, training runs inside your environment and the trained models never leave your network.

How is this different from LiteLLM or Portkey?

LiteLLM and Portkey are good load balancers and proxies. They route by rules you define. Token Station adds a learning layer: the router trains on your actual usage and improves with each version. Static rules decay as your product changes; a router that retrains on its own outcomes does not.

Can I set limits so one team doesn't use the whole budget?

Yes. You assign monthly token budgets per employee, team or department from the admin dashboard. The gateway enforces them in real time: a soft warning at 80% and a hard cutoff at 100%. Once a cloud budget is used up, that employee's traffic shifts to local models, and quotas reset at the start of each billing period.
